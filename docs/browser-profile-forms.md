# 浏览器普通资料表单

## 普通资料表单与用户接管

网页需要用户补充资料时，先 `read` 确认字段与当前值，再结合对话已有资料判断缺口。普通文字、简介、数字、日期、固定选项集中用 `tomako_request_form` 收集，避免用户逐个远程输入或来回回答。只询问未知项，保留页面已有值。表单传 `browser:{"site":"当前网站域名","path":"local-chrome 或 cloud"}`，路径来自当前浏览器状态；同一张交互卡会带现有的接管入口。这个元数据用于展示入口，不是绑定会话或授权凭据。

表单答案会保存到对话并返回给 Agent，不得称为“Agent 看不到”的安全表单。密码、验证码、卡号/CVC 等私密输入，以及上传、签署、CAPTCHA、复杂级联/拖拽/画布控件继续通过 `tomako_request_browser_help` 请用户在原网页操作，不用普通文字字段替代。

收到答案后，先 `status` 确认路径与控制状态，再 `read` 原网页，使用当前元素 ref 填写。`HUMAN_CONTROL` 时等待用户明确交还；提交或跳过表单不会交还控制。用户也可以接管网页亲自填写，再交还并跳过资料表单；此时读取并保留实际页面内容，不把跳过当成完成证明，不自动重新弹同一张表单。页面已跳转或字段发生变化时重新判断缺口，不按旧 ref 写入、不静默导航覆盖用户状态。仅填用户提交且网页仍需要的值，不编造空缺。

提交资料表单只表示用户提供了资料，网页最终提交沿用原任务授权。根据网站实际反馈核对结果，不能把表单回执当成网页提交成功。没有表单工具的旧回合可以在对话中一次询问普通资料，或按确实需要的步骤请求接管，不要求用户把私密输入发到聊天。

## 领域与交互边界

复用 `AskUserQuestion` 的 `form` 与 `userAction`，不新增端点或持久化状态。Java ChatSession 仍负责问题、答案与事务；Java Browser 仍负责租约、控制权和网页执行回执；cc-connect 只校验、传递表单与接管元数据。前端复用当前对话的表单与接管组件。元数据不承诺绑定固定页面，后续执行必须由 Agent 重新观察原页面。

验收覆盖：普通字段集中填写并实际落到网页；跳过不编造；取消不重开；接管期间禁止 Agent 写入；交还后保留手工输入；刷新后回读表单答案和网页结果。私密输入通道不在本期范围内。
